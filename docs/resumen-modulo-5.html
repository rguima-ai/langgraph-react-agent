01 · Arquitectura de grafos

Una cadena avanza. Un grafo decide.

Las cadenas sirven para secuencias previsibles. Un agente necesita bifurcaciones y ciclos: después de observar un resultado debe elegir si termina, reintenta o escala.

A

Cadena lineal

El próximo paso está predeterminado. Es ideal para procesos simples y repetibles.

Input→ Prompt→ LLM→ Output
→
B

Grafo con ciclos

El próximo nodo depende del estado. Puede volver atrás para corregir o buscar más información.

Agent⇄ Tools→ END
S

Estado

Es la memoria compartida que viaja por el grafo. Contiene datos, no conexiones de infraestructura.

N

Nodos

Funciones síncronas o async que leen el estado y devuelven una actualización parcial.

E

Aristas

Reglas de navegación. Pueden ser fijas o elegir el siguiente nodo según el estado.

Estado tipado y acumulativo

MessagesState ya define el historial con el reducer add_messages.

from langgraph.graph import MessagesState

class AgentState(MessagesState):
    """El historial se acumula automáticamente."""

# Un nodo devuelve solo lo nuevo:
return {"messages": [response]}

¿Qué hace un reducer?

Decide cómo combinar una actualización con el valor anterior. Sin reducer, una lista nueva puede reemplazar a la anterior. Con add_messages, se concatena y se preserva el historial.

🧠
Regla mental

El nodo no devuelve “todo el mundo”; devuelve solamente lo que cambió.

✍️
Otro patrón: escritor ↔ crítico

El escritor mejora un borrador, el crítico mide calidad y una arista vuelve al escritor hasta alcanzar el umbral. Siempre debe existir un máximo de revisiones.

02 · Tool Calling seguro

El modelo pide. Tu aplicación ejecuta.

El LLM no corre Python. Produce una solicitud estructurada con el nombre de una herramienta y sus argumentos; el servidor valida, ejecuta y devuelve la observación.

1

Nombre

Identificador estable y único, por ejemplo search_knowledge_base.

2

Descripción

El docstring explica qué resuelve y cuándo debe usarla el modelo.

3

Entrada

Pydantic define tipos, obligatoriedad, límites y significado de los argumentos.

4

Salida

Una respuesta previsible que el LLM pueda interpretar como observación.

Contrato de entrada

class SearchInput(BaseModel):
    query: str = Field(
        min_length=3,
        max_length=200,
        description="Dato concreto a buscar",
    )
    limit: int = Field(default=1, ge=1, le=3)

Herramienta asíncrona

@tool(args_schema=SearchInput)
async def search_knowledge_base(
    query: str,
    limit: int = 1,
) -> str:
    """Busca datos internos verificables."""
    results = await db.similarity_search(query, k=limit)
    return json.dumps({"results": results})
🔐
Least Privilege

Cada herramienta recibe solo los permisos mínimos. Nunca ejecutes SQL, comandos o código crudo producido por el LLM sin una capa estricta de validación y autorización.

El recorrido de una llamada

R

Reason

El LLM analiza el mensaje y las definiciones de tools. Decide que necesita información externa.

A

Tool call

Devuelve una estructura como {name, args, id}. Todavía no se ejecutó nada.

E

Execution

La aplicación valida los argumentos y ejecuta la función Python real.

O

Observation

El resultado vuelve como ToolMessage. El LLM reevalúa si ya puede responder.

03 · Ciclo ReAct

Pensar, actuar, observar… y repetir.

La autonomía aparece cuando la observación vuelve al agente. El modelo puede dar la respuesta final o producir una nueva llamada de herramienta.

ToolNode

Es el nodo especializado que recibe las solicitudes del LLM, busca la función correspondiente, la ejecuta y convierte la salida en mensajes de herramienta.

tools_condition

Inspecciona el último mensaje del modelo: si contiene tool_calls va a tools; si no, termina en END.

workflow.add_node("agent", call_model)
workflow.add_node("tools", ToolNode(TOOLS, handle_tool_errors=True))

workflow.add_edge(START, "agent")
workflow.add_conditional_edges(
    "agent",
    tools_condition,
    {"tools": "tools", END: END},
)
workflow.add_edge("tools", "agent")  # Esta flecha crea el ciclo.
🛑
Todo ciclo necesita un freno

recursion_limit=10 evita que un agente que nunca decide terminar genere costos y llamadas indefinidas.

04 · Checkpoints

La memoria que sobrevive al reinicio.

Un checkpointer guarda una fotografía del estado después de cada paso. Con el mismo thread_id, LangGraph puede recuperar la conversación y continuar.

01

Checkpoint

Snapshot del estado y del lugar del grafo donde terminó cada superpaso.

02

Thread

Secuencia de checkpoints agrupada bajo un identificador de sesión.

03

Time Travel

Permite inspeccionar estados anteriores, depurar o pausar para aprobación humana.

Persistencia asíncrona local

async with AsyncSqliteSaver.from_conn_string(
    "data/checkpoints.sqlite"
) as checkpointer:
    await checkpointer.setup()
    app = build_graph(model, checkpointer)
    result = await app.ainvoke(
        {"messages": [HumanMessage(content=question)]},
        config={
            "configurable": {"thread_id": "cliente-102"},
            "recursion_limit": 10,
        },
    )

Mismo ID, misma conversación

Primer turno

“Buscá los pedidos del cliente 102”.

2

SQLite

Guarda mensajes, tool calls y observaciones.

3

Segundo turno

“¿Y el último?” El agente recupera que hablábamos del cliente 102.

Antes de entregar

Errores que parecen pequeños y rompen agentes.

En agentes, la confiabilidad depende tanto de los límites como de la inteligencia del modelo.

Estado sobrecargado

No guardes clientes de DB, sockets o modelos dentro del State. Guardá solamente datos que deban viajar o persistir.

Nodos gigantes

Separá llamada al modelo, ejecución de tools y lógica de negocio. La granularidad permite testear y enrutar.

Docstring vago

“Busca datos” no alcanza. Describí fuente, alcance, cuándo usarla y qué no debe inventar.

Sin reducer

Una actualización puede borrar el historial. Para chat usá MessagesState o add_messages.

Bucle infinito

Definí recursion_limit y una política de reintentos. Un ciclo sin salida cuesta dinero.

Error sin observar

Convertí timeouts y fallos previsibles en resultados controlados que el agente pueda interpretar.

Estado sucio

El historial crece. En sistemas largos necesitás resumir, recortar o separar memoria de corto y largo plazo.

Secretos en Git

La API key vive en .env, que debe estar ignorado. El repo solo incluye .env.example.

🧪
Probá también el camino de fallo

No alcanza con el “happy path”. Simulá un timeout, comprobá que el proceso no se caiga y que el resultado pueda volver al agente.

Autoevaluación

Si podés explicar esto, entendiste.

Abrí cada pregunta después de responderla mentalmente.

¿Cuál es la diferencia entre invocar y ejecutar una herramienta?

El LLM invoca: produce nombre y argumentos. La aplicación ejecuta: valida y llama a la función real.

¿Qué flecha convierte el flujo en un ciclo ReAct?

La arista que vuelve de tools a agent. Sin ella, el modelo no puede observar y reconsiderar.

¿Por qué thread_id no es lo mismo que historial en memoria?

El ID identifica una secuencia persistida de checkpoints. Una lista en RAM desaparece cuando termina el proceso.

¿Quién decide si el grafo termina?

El LLM, al devolver una respuesta sin tool_calls. tools_condition interpreta esa salida y enruta a END.

¿Por qué el test usa un modelo simulado?

Para comprobar de manera determinista dos ciclos, sin depender de una API, gastar tokens o confiar en una decisión probabilística.

Constructor donde se registran esquema, nodos y aristas.

Unidad de trabajo que lee estado y devuelve cambios parciales.

bind_tools

Principio de conceder solo los permisos indispensables.
